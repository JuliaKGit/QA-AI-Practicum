# BuddyTime API catalog (test.buddytime.ca)

Captured **2026-10-16** while signed in as the main test family (`playwright/.auth/user.json` / `bt_token` + `Authorization: Bearer`). Pages visited in order: Dashboard (`/app`), Friends, Communities, Availability, Playdates, Birthdays, Profile (`AppRoute`). Static assets, `_next` data, images, fonts, and analytics were excluded.

On Dashboard only: created one child (`POST /api/v1/children`) and removed it (`DELETE /api/v1/children/{id}`) using the child id from the create response (204).

> **Note:** Playwright MCP tools were blocked in this environment (`beforeMCPExecution` hook failed closed). Traffic was recorded with local Playwright using the same storage state and network capture equivalent to `browser_network_requests`.

## Not yet tested

- **Pagination / filtering** — all list endpoints returned a single unpaginated JSON array; query params (if any) were not exercised.
- **Error response shapes** — validation errors (4xx) and server errors (5xx) were not triggered on these routes.
- **Rate limits** — not observed.
- **Unauthenticated GET access** — without `Authorization` / `bt_token`, every catalog GET above returned **401** (recorded 2026-10-16 API test pass). Expired-token behavior was not exercised.
- **Write endpoints not hit on this pass** — UI exposes actions that likely call APIs we did not invoke (read-only browsing except child create/delete): e.g. profile save (`Save my details` / `Save family details`), availability save, playdate propose/respond/cancel, friend invite/remove, community join/create, birthday/party RSVP, avatar change, logout/login token refresh. These remain unknown until called.
- **Child remove via UI** — `remove` buttons exist on Dashboard; delete was confirmed with `DELETE /api/v1/children/{id}` using the id from the create response (204). Mapping a specific `remove` control to a given child row was not fully characterized (child first name did not appear in the a11y tree immediately after create without reload).
